# External libraries

This folder is the canonical external-runtime inventory. `manifest.json` records dependency versions, architecture, Full/Lite edition policy, source/package identity, archive and file hashes, license identifiers, acquisition/verification date, shipped license/source paths and platform evidence. Runtime binaries are part of the generated Full Edition release package, not ordinary Git history; the Lite Edition contains only application code, metadata and documentation.

Assimp 6.0.5 is bundled for OBJ-to-GLB conversion. It was obtained as the signed `mingw-w64-clang-x86_64-assimp` package from the official MSYS2 Clang64 repository. The six-package runtime dependency tree and dependency edges are recorded in the manifest; package signatures and integrity were checked by pacman before extraction. Clang64's virtual `cc-libs` and `gcc-libs` requirements are satisfied by its Apache-2.0-with-LLVM-exception `libc++` package, not by the separate GNU GCC runtime package. Only the executable, required DLLs and license texts are shipped. Package caches and extraction staging folders are not release content.

FFmpeg 9.0.2 is selected from Gyan's x64 shared full build through the official WinGet package `Gyan.FFmpeg.Shared`; the package archive hash and upstream FFmpeg source revision are pinned above. The exact runtime reports `--enable-gpl --enable-version3 --enable-shared --enable-libssh`, so the Full package preserves the GPLv3 text, Gyan attribution/README, exact upstream source revision, source archive reference and actual `-buildconf` output in generated `FFmpeg/SOURCE.txt`. The Full package includes only `ffmpeg.exe`, `ffprobe.exe` and their required runtime DLLs; `ffplay.exe`, development headers and import libraries are excluded. The package builder verifies the archive hash, each runtime file hash/size/architecture, version, required capabilities, license and required build flags before including files.

At startup, unless update checks are skipped, the application makes bounded HTTPS requests to official upstream and package-manager metadata endpoints. It compares stable upstream versions and package rebuild revisions and reports available updates; checks are read-only. Offline/network errors are non-fatal. A maintainer choosing to update must use the vetted package-manager route, inspect the complete new runtime dependency tree and license obligations, stage and verify the candidate, activate it transactionally, then remove the superseded files only after post-activation checks succeed. The manifest, notices, packaging, tests and docs must be synchronized in the same change.

Keep each bundled Assimp package's full license text in `Assimp/licenses/`. The FFmpeg license and upstream README are extracted from the verified WinGet archive into each Full release package. Both editions include the root `THIRD-PARTY-NOTICES.md`; Lite excludes runtime binaries and runtime license payloads. The project source remains under Apache-2.0; third-party terms remain applicable to their respective components. The stable versions checked on 2026-10-16 were FFmpeg 9.0.2 and Assimp 6.0.5/MSYS2 package 6.0.5-2; no newer stable package was selected. The reviewed FFmpeg 9.0.2 advisories are enumerated in the manifest and release notes.
